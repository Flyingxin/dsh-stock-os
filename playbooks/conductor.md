# 总纲：这台机器怎么转

## 它解决的不是"选哪只股"，是"凭什么动手"

一个人亏钱通常不是因为不知道好公司，而是因为：买的时候没有规则，跌的时候没有预案，卖的时候没有记录，复盘的时候只剩情绪。

所以这套东西的三条铁律是：

1. **不预测，只准备。** 没有任何一步要求你判断明天涨跌；每一步只要求你把"如果发生 X 我就做 Y"提前写下来。
2. **先有规则，再有钱动。** 没有策略宪法，`stock_os` 会直接拒绝建仓记录。
3. **没有记录的动作等于没有发生。** 每一笔买卖、每一次改规则，都必须留痕，包括破例。

## 状态机

```
idea ──▶ research ──▶ plan ──▶ open ══▶ hold ──▶ closed
  │           │          │        ║        │          │
  └───────────┴──────────┴────────╨────────┘          ▼
                          任何阶段可退出              review
```

- `hold` 是停留最久的阶段，加仓、减仓都发生在这里，阶段本身不变。
- 回到 `research` 是允许的（`plan → research`）：调研结论被证伪时，退回重做，而不是硬着头皮买。
- `closed` 只能由"持仓归零"进入，然后一定要走 `review`。

## 八步与手册的对应

| 步 | 做什么 | 手册 | 写进档案的字段 |
|---|---|---|---|
| ① 买前调研 | 行业/生意/护城河/财务/估值/内部人 | `research` | `verdict` |
| ② 策略宪法 | 把结论翻成数字与红线 | `plan` | `constitution` + `plans.drawdownPlan` |
| ③ 建仓 | 信号到了，按首笔上限买 | `entry` | `position` + 流水 |
| ④ 加仓 | 只在假设被验证时加 | `add` | `position` + 流水 |
| ⑤ 持有 | 监测、预警、不改规则 | `hold` | `plans.reviewDueAt` + 流水 |
| ⑥ 减仓 | 三类理由，分批卖 | `reduce` | `position` + 流水 |
| ⑦ 清仓 | 红线触发，一次卖完 | `exit` | `stage=closed` |
| ⑧ 统计总结 | 复盘、算账、改规则 | `review` | 流水 `kind=review` |

## 每次对话的标准动作

1. `stock_os action=get` 看这只股票现在在哪个阶段、有没有逾期复盘。
2. 按阶段读手册：`stock_playbook stage=...`。
3. 做这一阶段该做的事，产出写回档案（`verdict` / `constitution` / `plan` / `trade`）。
4. 动作之前先 `action=guards`（有现价时传入），让规则先说话。

## 三本账

| 账本 | 存什么 | 回答什么问题 |
|---|---|---|
| 档案 `SYMBOL.json` | 结论、宪法、仓位、回撤预案 | 我当初为什么买？规则是什么？ |
| 流水 `journal.jsonl` | 每笔动作、每次改规则、每次破例 | 我到底做了什么？ |
| 复盘（流水里的 `review`） | 结果归因、规则修正 | 我是靠本事还是靠运气？ |

## 自动化任务的边界

可以自动做的：盘后检查是否触及止损/止盈、复盘是否逾期、财报与公告日提醒、异常波动提醒。

**不能自动做的：下单。** 插件不接券商、不给买卖指令。所有交易由人执行、由人确认，插件只负责"提醒你规则怎么写的"。

## 反自欺清单（每次想动手前扫一眼）

- 我是在执行一条已经写下的规则，还是在为一个已经做出的决定找理由？
- 如果这笔亏 20%，我知道自己会怎么做吗？（答不上来就不能买）
- 这条规则是买之前写的，还是刚刚写的？
- 我改规则，是因为新证据，还是因为价格让我难受？
