# 每个阶段用什么提示词

> 由 `lib/prompts.js` 生成，插件面板的「提示词」标签页读的是同一份数据。
> 把 {{symbol}} 换成股票代码（如 600519.SH）即可直接粘进对话。

## ① 买前调研

适用：还没有结论，或者数据不齐

### 从零调研一只票

```text
调研 {{symbol}}{{namePart}}。先 stock_data 把近五年营收/净利润/经营现金流等科目按年份写进去，用 action=check 确认通过；再 stock_notes 检索判断依据、stock_charts 出图看趋势；然后按 stock_playbook stage=research 的清单给结论，用 stock_os verdict 写入（写清异常、硬排除、数据截止日）。
```

### 只补数据

```text
{{symbol}} 的五年数据集还不完整：先 stock_data action=check 看缺什么，缺的科目去年报里找，补完写回 stock_data。不要在没有通过 check 前写 verdict。
```

### 看结论报告

```text
用 stock_report 给 {{symbol}} 生成结论报告（HTML），然后把结论带、12 项排雷检查里判成"异常"的条目逐条解释一遍。
```

## ② 策略宪法

适用：已经有 pass/watch 结论，准备定规则

### 把结论翻成规则

```text
基于 {{symbol}} 的买前结论，跟我一起定策略宪法：仓位上限、分几批、首笔比例、止损、最大回撤、止盈、加仓条件、减仓条件、退出信号、失效条件、复盘周期。不确定的地方先问我，定完用 stock_os action=constitution 写入，再写 plan（回撤预案 + 下次复盘日期）。
```

### 检查现有宪法是否自相矛盾

```text
读 {{symbol}} 的档案，把 constitution 和 plans 摊开，指出互相矛盾或根本执行不了的地方（例如止损位在回撤预案的减半线之上、加仓条件与"不加仓"冲突），给出修改建议，我确认后再写入。
```

## ③ 建仓

适用：宪法与回撤预案都写好了，等信号

### 评估现在能不能建首笔

```text
{{symbol}} 当前价 {{price}}。先用 stock_os action=guards 跑规则，再对照宪法看首笔仓位是否合规、风险预算是否够（(现价−止损价)×股数 ≤ 总资金×2%）。给出结论和具体股数，我确认后执行 trade=open。
```

### 记录建仓

```text
按宪法建首笔：{{symbol}} {{qty}} 股 @ {{price}}，理由是……。用 stock_os action=trade trade=open 写入，附上估值与关键指标快照。
```

## ④ 加仓

适用：已持仓，且满足宪法里的加仓条件

### 检查加仓条件

```text
{{symbol}} 现在 {{price}}，成本 {{avgCost}}。逐条核对宪法里的加仓条件是否成立（触发的是哪一条、证据是什么），并算加仓后的仓位占比是否超限。不成立就明确说不加。
```

## ⑤ 持有 / 风控

适用：已建仓，进入日常跟踪

### 盘后风控检查

```text
{{symbol}} 今日收盘 {{price}}。跑 stock_os action=guards，对照止损/止盈/失效条件，告诉我今天有没有触发；没触发就只回一句"无动作"。
```

### 异常事件研判

```text
{{symbol}} 出了这件事：……。判断它属于"噪音/需要跟踪/触发失效条件"哪一类，依据是 stock_notes 里的哪一节，结论写进 stock_os action=journal（kind=notice）。
```

### 定期复盘

```text
{{symbol}} 到了复盘日。按 stock_playbook stage=review 的四问过一遍：当初的买入理由还成立吗、有没有出现宪法没覆盖的情况、仓位还合适吗、要不要改规则。
```

## ⑥ 减仓

适用：触发减仓条件，或仓位过重

### 评估减仓

```text
{{symbol}} 触发了我宪法里的这一条：……。算出应减多少股（不超过单笔上限），确认减完后的仓位与成本，我确认后执行 trade=reduce。
```

## ⑦ 清仓

适用：触碰红线，或投资前提不成立

### 执行清仓

```text
{{symbol}} 触发了退出信号：……。确认这是"事实触发"而不是"情绪触发"，用 trade=close 清掉全部 {{qty}} 股，并写明这次错在哪。
```

## ⑧ 复盘总结

适用：清仓后，或回撤预案被触发

### 写复盘

```text
对 {{symbol}} 这笔交易做复盘：按当时能看到的信息重放一遍，哪些是可预见的、哪些是运气；把结论写进 stock_os action=journal（kind=review），并给出要不要改宪法的建议。
```

### 组合层面统计

```text
把我所有档案的流水统计一遍：胜率、平均盈亏比、最大回撤、最常见的违规动作（force 记录），指出我最该改的一个习惯。
```

## 三条硬规则

1. 数据没通过 `stock_data action=check` 之前，不要写 `verdict`（唯一例外是 `na`：拿不到数据本身就是结论）。
2. 没有策略宪法，`trade open` 会被拒绝；宪法里的每一条都要能被触发、能被验证。
3. 每次动作都要留流水（`journal` / `trade` 的 reason 写"为什么"，不写"做了什么"）。
